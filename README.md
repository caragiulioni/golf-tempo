# Golf Tempo Trainer

A golf tempo trainer based on Tour Tempo, with one addition: a fourth beat for a small movement in your swing. It runs in the browser first, and may become a phone app later.

This project is planned before it is built. If you think like a planner, you will feel at home here. Each folder below plays a role you will recognize from a planning project.

## The map

| Folder / file | What it is | Planning equivalent |
|---|---|---|
| `_references/` | Source material we started from: the original spec, a recording of Tour Tempo, screenshots, layout mockups | Site survey and background studies |
| `.kiro/steering/` | Standing rules and decisions that apply to every piece of work | Zoning code and design guidelines |
| `.kiro/specs/` | Detailed plans for each feature, plus the ordered list of them | Project plans and the master schedule |
| `docs/` | Working documents: the questions, the decisions, and the guide for moving to phones | Consultation record, decision register, handover documents |
| `docs/client_questions.md` | Questions only you can answer | Stakeholder consultation |
| `docs/dev_questions.md` | Open technical decisions, and the ones already made | Decision register |

Each folder has its own README with more detail.

## How a project moves through here

1. **Survey.** Gather what exists (`_references/`).
2. **Set the rules.** Write down decisions that apply everywhere (`.kiro/steering/`).
3. **Consult.** Ask the people affected and record the answers (`docs/client_questions.md`).
4. **Plan each piece.** One spec per feature, in order (`.kiro/specs/`).
5. **Build in small phases.** Each phase is small enough to check and review.
6. **Hand over.** Document how to take it further (`docs/`).

Planning first matters because Kiro does what the plan says. A clear plan gives good results, and a vague one gives guesses.
