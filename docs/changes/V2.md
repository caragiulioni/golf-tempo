# V2 Change Log

**Branch:** `dev-V2`, started from `main` at the tag `prototype-v1` (November 2026).
**Goal:** move the app from a Tour Tempo clone to a stand-alone app that explains itself (see the guiding principles in `.kiro/steering/product.md`).
**Rules:** `.kiro/steering/prototype-versions.md`.

Every change is one commit on `dev-V2`, and its message starts with the ID. To find a change's commit:

```
git log --grep "V2-03" --oneline
```

To undo it: `git revert <hash>`, then mark the entry **Reverted** here. Revert newest first, and check "Depends on" before reverting.

**Status values:** **Planned** (in the plan below, not built), **Landed** (on `dev-V2`), **Reverted** (undone, with the reason), **Released** (merged into `main`).

### Details

**V2-01: Play button smaller.** About 20 px (first 10, then another 10 after review) smaller in width and height than now, at every size. Check: the button still meets the 44 pt minimum tap size on phones.

**V2-02: Weight shift default 0.75.** Long Game and Short Game both start at 0.75 of the way from takeaway to top (was 0.70 and 0.60). The defaults live in `src/engine/weightShift.ts`, so this is an engine change, approved as an exception (`.kiro/steering/prototype-versions.md`). Built in the timing engine context window. Notes:
- Engine tests that check 0.70 and 0.60 change with it.
- Applied values saved on a device (CONFIG) still win over the default. Mike keeps his own values until he presses Reset.
- Update `product.md`, `timing-engine.md` and the calibration guide in the same commit.

**V2-03: Sound toggles.** Two toggles directly below the Current session card:
- **Background loop:** on or off (moves here from the controls area; off by default, as now).
- **Weight shift:** on or off (on by default). Off plays the three Tour Tempo beats only.
- Takeaway, top and impact always play, so the app is never silent and no "never silent" rule is needed.
- Weight shift off also hides the gold diamond and its label on the scale (decided).
- Changing either while playing follows the existing rule: stop, short pause, new run from beat 1.
- The Audio lab already has this logic (`includeWeightShift`). Copy the behavior, not the lab's code.
- Open: on laptop the card is in the left column; check where the toggles sit there.

**V2-04: Preset data.** Each Long Game preset gets a group in `src/engine/presets.ts`: Gameplay (18/6, 21/7, 24/8, 27/9, 30/10) or Practice Drills (42/14, 60/20, 84/28). 120/40 and 168/56 are removed. Short Game has no groups. Approved engine exception (Practice Drill timing). Built in the timing engine context window.

**V2-05: Gameplay / Practice Drills toggle.** Long Game only. Two linked buttons below the Tempo label: **GAMEPLAY** and **PRACTICE DRILLS**. Selecting one deselects the other. Gameplay shows the 5 Gameplay tempos, Practice Drills the 3 drills. Short Game shows no toggle.

**V2-06: Tempo slider.** The preset buttons become one stepped slider that snaps to each tempo. The section label "Available sessions" becomes **"Tempo"** (the wording can change later).
- Long Game, Gameplay: 5 steps (18/6 to 30/10), starts at 24/8 (the middle).
- Long Game, Practice Drills: 3 steps (42/14, 60/20, 84/28), starts at 60/20 (the middle).
- Short Game: 6 steps (14/7 to 24/12), starts at 24/12, as now.
- Reuse the existing `Slider` component and the snap helper (`snapToStep`), per the Reuse check.
- Open: whether each group remembers its last position when switching back, or returns to its default.

**V2-07: Drill timing.** On Practice Drills, each swing plays once, then a recovery measure, then a countdown 4, 3, 2, 1 on the hi-hat that leads into the next takeaway. Lines up with the loop whether it is on or off. Full design: `docs/ideas.md`, idea 2, "Drill timing", and `docs/drills-handoff.md`. Approved engine exception. Built in the timing engine context window. Open: whether Play starts with a countdown or straight on takeaway.

**V2-08: Countdown on screen.** The numbers 4, 3, 2, 1 shown at TAKEAWAY on the scale, with a pulse, following the audio schedule (never a separate timer). What the UI decides: `docs/drills-handoff.md`, section 6.

**V2-09: Configure weight shift panel.** The weight shift settings move from the CONFIG screen into an expandable panel at the very bottom of the main screen, below the Tempo slider (the last item when you scroll down).
- Collapsed: a label, "Configure weight shift".
- Open, in order: the blurb "The weight shift typically occurs around 75% of the backswing. Fine-tune this position to match your swing and natural movement.", then How to, then the configure controls (slider, − and +, APPLY, RESET, EXPORT).
- Unapplied changes: closing the panel with changes not applied shows the existing yes/no confirmation dialog.
- The Config item stays in the header menu for now. It will be removed later, since the panel replaces it.
- CONFIG code stays in `src/config-mode/`, so it can still be removed in one piece.

**V2-10: Archetype and "Good for" text.** The Current session card shows the selected tempo's archetype and "Good for" line from the tables in `docs/ideas.md`, idea 1. The big frame count (for example 30/10) stays. Text lives in the preset data. Open: the layout, and the final wording of each row.

**V2-11: Browser tab title.** The browser tab shows "Golf Tempo", because the web build takes its page title from `"name"` in `app.json`, which was never renamed. Change it to "Swing Tempo", to match `APP_NAME` in `src/ui/brand.ts`. This also sets the app name for a future native build, which should match anyway. Leave `"slug"` (`golf-tempo`) alone: it is an internal ID. Independent, so it can land at any point; if it lands earlier, renumber the plan first. Check: build for web, open it, and read the tab title.

## Entry format

```
## V2-NN: <short title>
- Status: Landed / Reverted (reason) / Released
- Idea: `docs/ideas.md`, idea N (or "new")
- What changed: plain-language summary, as the user sees it.
- Why: the problem it solves, and which guiding principle it serves.
- Files: main files touched.
- Docs updated: which docs were changed in the same commit.
- Depends on: other V2 IDs, or "none".
- Reuse check: components and tokens checked; what was reused, extended or created.
- Check: how it was verified (what to look at, on which devices).
- Porting: web-only parts (with file paths) and what replaces them on native; what carries over unchanged; what needs testing on a real device. "None" if nothing changes for the port.
- Accessibility: what a screen reader says for each new or changed control (label, role, state, value), and what happens to focus. Web-only keyboard handling goes in the Porting line. "None" if no controls change. See `docs/porting-guide.md`, "Accessibility on a phone".
```

**Porting guide:** the Porting lines are written with each change, in its commit, so they revert with it. When V2 merges into `main`, one V2 entry in `docs/porting-guide.md` is compiled from the Porting lines of the changes still marked Landed. Reverted changes are left out. Anything that reaches `main` is in the porting guide.

## Changes

## V2-01: Play button and tempo numbers smaller
- Status: Landed
- Idea: new
- What changed: the round play/pause button is 20 px smaller in width and height at every screen size: phone 75 to 55, tablet 120 to 100, laptop 128 to 108. It appears in the Current session card on the main screen and on the CONFIG screen. The tempo numbers (for example 30 / 10) and the slash are also 10 px smaller (phone 60 to 50, tablet and laptop 120 to 110), and the extra side padding around the slash is removed (the spaces around it remain).
- Why: the button dominated the Current session card. A smaller button gives the tempo numbers and the scale more room, so the card reads at a glance (principle 1).
- Files: `src/theme/tokens.ts` (`layoutSizes`, `typeSizes.tempo`), `src/ui/components/Badge.tsx` (removed `tempoSlash` style).
- Docs updated: this log, and `docs/design-brief.md` (new "V2 size adjustments" section; the mockup `docs/design/main-screen.html` is left as the original). `.kiro/steering/prototype-versions.md` also changed (review-before-merge rule), as a separate process change, not part of the V2-01 commit.
- Depends on: none.
- Reuse check: read `PlayButton.tsx`, `src/theme/tokens.ts`, `src/ui/components/README.md`. Read `Badge.tsx`, `AppText`. Reused the `layoutSizes.playButton` and `typeSizes.tempo` tokens. No new component, token or style; one style removed. The play/pause icon is 40% of the button, so it shrinks with it.
- Check: `npm run typecheck` and `npm test` (340 tests) pass. Phone size 55 is above the 44 pt minimum tap size. Visual check at phone, tablet and laptop widths still to be done by the developer.
- Porting: none. `layoutSizes` is plain numbers in density-independent units, so it carries over unchanged to native. Check the button looks right on a real phone.
